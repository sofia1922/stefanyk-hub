# Автентифікація й захист облікових записів

## Що реалізовано

- Реєстрація через сервер із перевіркою університетської пошти, навчальних даних і ролі. Викладач має бути в `allowed_teachers`; самостійна реєстрація адміністратора заборонена.
- Пароль: 8–128 символів, велика й мала літери, цифра, спеціальний символ. Перевірка на клієнті та сервері, невеликий список поширених паролів, підказка щодо стійкості.
- Серверна CAPTCHA: PNG з випадковими цифрами, строк 3 хвилини, одна спроба. Відповідь не надсилається клієнту; сервер зберігає лише її SHA-256. Оновлення зображення доступне на формі.
- Активація пошти: випадковий 256-бітний токен, у базі лише SHA-256, одноразове використання, строк 60 хвилин. Профіль стає доступним після активації. Є повторне надсилання й статус активації в профілі.
- Після 5 невдалих спроб вхід для адреси обмежується на 15 хвилин від початку вікна. Ліміти перевіряються транзакціями Firestore і переживають перезапуск сервера. Є також ліміти за адресою мережі та для CAPTCHA, листів і 2FA.
- Адміністратор у профілі → «Безпека облікового запису» бачить останні 100 подій, перші 100 акаунтів, кількість спроб, може блокувати й розблоковувати акаунти, скидати тимчасове блокування. Власне блокування заборонено.
- TOTP 2FA: сумісність із Google Authenticator та іншими RFC 6238 застосунками, 6 цифр / 30 секунд. Підключення вручну за ключем. Увімкнення й вимкнення в профілі потребують коду; після зміни потрібно ввійти заново. Для початку налаштування потрібен недавній вхід (до 10 хвилин).
- TOTP-секрет шифрується AES-256-GCM із прив’язкою до UID. Код не приймається повторно; дозволений зсув часу ±30 секунд. Для завершення входу є обмежений у часі challenge і не більше 5 спроб коду.
- Google-вхід проходить через сервер і також потребує TOTP, якщо його ввімкнено. Код інтеграції є; справжній Google-вхід потребує конфігурації OAuth у Firebase та не перевіряється демо акаунтами.
- Відновлення пароля: лист із випадковим одноразовим токеном на 30 хвилин, новий пароль перевіряється сервером. Старі сесії й раніше видані посилання після зміни пароля стають недійсними. Відновлення пароля не вимикає 2FA.

## Як організовано доступ

Android → REST API безпеки → Firebase Authentication / Firestore.
Після перевірки пароля, активації, блокування та другого фактора сервер видає Firebase custom token з `secure_session` і `security_version`. Android обмінює його через `signInWithCustomToken()`.
Правила Firestore та Storage вимагають ці claims і актуальну версію серверного стану. Простий прямий Firebase-вхід за паролем не дає доступу до даних. Зміна 2FA, пароля або блокування змінює версію та закриває старим токенам доступ.

Колекції `security_accounts`, `security_tickets`, `security_limits`, `security_audit` доступні лише серверному Admin SDK. Клієнт не може записувати журнал, змінювати блокування, читати токени або TOTP-секрет. Події не містять паролів, OTP чи токенів; IP зберігається як хеш.
Адміністративні запити перевіряють роль у базі. Тимчасові записи очищаються сервером кожні 5 хвилин; для журналу слід задати потрібний організації строк зберігання.

Паролі не записуються у Firestore, журнал чи Android preferences. Їх хешування й перевірку забезпечує Firebase Authentication, що використовує модифікований scrypt. SHA-256 тут застосовано лише для випадкових токенів і ключів записів, не для паролів.

## Локальна демонстрація

1. У корені виконайте `.\tools\demo\start.cmd`. Він запускає Auth / Firestore / Storage, початкові дані та API на порту 8787.
2. Запустіть debug-збірку, увімкніть «Локальне тестування». Сервер доступний Android Emulator за `http://10.0.2.2:8787`.
3. Для наявних демонстраційних акаунтів пароль `DemoPass123!`. Нову реєстрацію перевіряйте іншою університетською адресою.
4. Листи емулятора **не надсилаються в справжню поштову скриньку**. Тестові листи записуються у `tools/demo/.security-local/verify-<hash>.json` та `reset-<hash>.json`. Відкрийте `link` у браузері комп’ютера, підтвердьте дію й поверніться в застосунок. JSON містить строк дії.
5. У профілі → «Безпека облікового запису» увімкніть TOTP, додайте ключ до автентифікатора, підтвердьте код і ввійдіть знову. Збережіть ключ для відновлення доступу: окремих recovery codes поки немає.
6. Адміністратор: `admin.demo@pnu.edu.ua`. У тому самому розділі доступні журнал та блокування.

Якщо емулятори вже запущені старим скриптом, API можна запустити окремо:

```powershell
$env:SECURITY_MODE = 'demo'
node tools/demo/security/server.mjs
```

Не запускайте другий екземпляр API на тому самому порту. Ключ шифрування локального TOTP зберігається в `.security-local/encryption.key`; не видаляйте його, якщо хочете зберегти налаштовані секрети.

## Справжня пошта й запуск через інтернет

Локальна реалізація готова для демонстрації. У хмарний Firebase сервер та оновлені правила автоматично не розгорталися. Для production потрібні:

- Node.js 20+, `npm ci --prefix tools/demo`, облікові дані Admin SDK через Application Default Credentials з правом підписувати custom tokens. Ключ сервісного акаунта ніколи не додається в APK чи git.
- Змінні `SECURITY_MODE=production`, `GCLOUD_PROJECT`, `FIREBASE_WEB_API_KEY`, `SECURITY_PUBLIC_URL=https://...`, `SECURITY_ENCRYPTION_KEY` (випадкові 32 байти в base64), `SMTP_URL`, `MAIL_FROM`. Приклад без секретів: `tools/demo/security/production.env.example`.
- Постійний ключ AES із секретного сховища та його резервна копія. Втрата ключа робить наявні TOTP-секрети непридатними. Ротація потребує міграції зашифрованих значень.
- HTTPS перед API. Ліміт за IP бере фактичну адресу сокета та не довіряє довільному `X-Forwarded-For`; за reverse proxy він діятиме на адресу проксі. Налаштуйте окремий ліміт за IP на довіреному ingress.
- Увімкнені провайдери Email/Password і Google, налаштовані OAuth Web Client ID, SHA-сертифікати Android, дозволені домени Firebase. Поточний `google-services.json` має відповідати цьому самому проєкту.
- Політика паролів Firebase має бути в режимі **Require**, мінімум 8, великі/малі літери, цифра та non-alphanumeric. Це закриває можливість зміни пароля на слабкий через прямий API Firebase. Також увімкніть захист від переліку email.
- Оскільки Auth є публічним сервісом, прямий signup Firebase може створити лише Auth-запис без нашого профілю; він не пройде серверний вхід і правила доступу. Для повної заборони прямого створення Auth-записів налаштуйте обмеження клієнтської реєстрації / blocking functions у Firebase Identity Platform і перевірте вплив на Google-провайдер. CAPTCHA в цій реалізації обов’язкова для реєстрації через наш API та створення профілю.
- Розгорнуті `firestore.rules` і `storage.rules`. Після оновлення користувачам зі старими сесіями потрібно ввійти через API заново. Перед запуском створіть початковий ADMIN-профіль через довірене адміністрування.
- Android збирається з `-PSECURITY_API_URL=https://your-host`. Без цієї адреси основний режим показує пояснення; автоматичного обходу серверних перевірок немає. HTTP дозволений лише для локальних адрес у debug.

Публічні download-token URL у Firebase Storage дають доступ до конкретного файла як посилання для поширення; їх не слід використовувати для конфіденційних файлів. Наявні навчальні матеріали використовують такі посилання. Перевірки серверної сесії захищають базу та звичайні запити Storage SDK, але не відкликають уже видані публічні посилання.

## Перевірки

При запущених емуляторах та API:

```powershell
node --test tools/demo/security/crypto.test.mjs
node tools/demo/security/integration.mjs
node tools/demo/verify.mjs
```

Криптографічні тести включають офіційні вектори RFC 6238. Інтеграційні перевірки створюють окремий тестовий акаунт і видаляють його після завершення: CAPTCHA, слабкий пароль, активація, строки дії, повторне використання токенів, TOTP, заборона обходу через прямий Firebase-вхід, блокування, права адміністратора й відновлення пароля.
Часті повторні запуски також підпадають під справжні серверні ліміти; при їх вичерпанні дочекайтеся завершення вікна.

Джерела: [Firebase custom tokens](https://firebase.google.com/docs/auth/admin/create-custom-tokens), [Firebase password hashing](https://firebase.google.com/docs/cli/auth), [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238).
