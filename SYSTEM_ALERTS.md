# Глобальні системні сповіщення

Адміністратор: профіль → вкладка «🚨 Системні» (рядок вкладок прокручується) → «Глобальне сповіщення». Оберіть тип, введіть текст до 1000 символів, підтвердьте аудиторію і опублікуйте.

Усі авторизовані користувачі бачать спільний банер над каталогом і профілем незалежно від ролі чи дисципліни. Натискання відкриває повний список активних повідомлень. Порядок: важливі → технічні роботи → інформація; усередині типу — новіші першими. Читач не приховує банер назавжди.

Адміністратор може зняти банер із підтвердженням; запис зберігається в історії. Його можна закріпити повторно. Дата показує початкову публікацію. Текст після публікації незмінний: для виправлення зніміть старий банер і опублікуйте новий.

Firestore: `system_alerts/{autoId}` із полями text, level, active, authorId, createdAt. Rules дозволяють публікацію й зміну active лише верифікованому адміністратору. Час публікації встановлює сервер. Студенти й викладачі мають тільки читання. Підписки знімаються при виході з екрана/акаунта.

Це банер у відкритому додатку, а не системні Android push-сповіщення. При закритому додатку доставка не виконується. Банер також не перекриває модальні діалоги ридера; після закриття діалогу він доступний на основному екрані. Для push потрібні Firebase Cloud Messaging, серверна відправка через Admin SDK/Cloud Functions, реєстрація пристроїв і дозвіл Android на сповіщення. Не можна зберігати серверний ключ відправки в APK.

У разі відсутності мережі може відображатися кеш Firestore. Публікація вважається завершеною після серверного підтвердження; відправка офлайн може очікувати підключення. Система не гарантує екстреної доставки і не замінює офіційні канали оповіщення.

Перед використанням розгорніть правила:

```powershell
firebase deploy --only firestore:rules --project stefanykhub
```

Додаткові складені індекси не потрібні: користувачі отримують `active == true`, адміністратор — історію, сортування виконується в додатку. Для значної історії варто додати пагінацію.
