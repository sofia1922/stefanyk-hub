# Пульс Університету

Адміністратор → Профіль → прокрутіть рядок вкладок → «📊 Пульс».

## Активність

Відкритий застосунок надсилає heartbeat раз на хвилину та при вході в акаунт. У фоні цикл зупиняється. `presence/{uid}` містить `lastSeen` (серверний timestamp), `sentAt` (час відправника). Дані доступні тільки адміністратору; користувач може оновити лише свій запис. Rules відхиляють відкладені записи, старші за дві хвилини, й надто майбутні timestamps. Неправильний годинник пристрою може призвести до відхилення heartbeat.

- Онлайн ≈ кількість унікальних UID із сигналом за останні 2 хвилини. Це оцінка, не постійне socket-з'єднання; після закриття додатка користувач може ще до 2 хвилин вважатися онлайн.
- За тиждень — унікальні UID із сигналом за останні 7×24 години, усі ролі включно з адміністратором.
- Старі входи до встановлення оновлення не відновлюються. Один UID на кількох пристроях рахується один раз.
- Пристрої без зв'язку не дають актуального heartbeat. UI перераховує часові вікна раз на 30 секунд, підписки Firestore оновлюються автоматично.

## Рейтинги

Collection group `activity` читається лише адміністратором. Враховуються події `DOWNLOAD` зі встановленим серверним timestamp у `materials/{id}/activity/{eventId}`. Це успішні завантаження студентів з модуля Material Analytics, за весь доступний час збору. Перегляди й кеш читання не включено. Кілька фактичних завантажень одним студентом можуть створювати кілька подій.

Топ-5 дисциплін і викладачів визначається сумою подій за матеріалами поточного каталогу. Викладачі групуються за teacherId; для старих матеріалів без ID — за ім'ям. Назви беруться з поточного каталогу. Події видалених матеріалів включені до загального числа завантажень, але не до рейтингу; їх кількість показується окремо. Це клієнтська телеметрія, а не захищений від накручування аудит. Для великих обсягів потрібні серверні агрегати: зараз адміністратор читає всі події, що збільшує кількість оплачуваних читань.

## Фактичний обсяг Storage

Android не має повноважень адміністративно інвентаризувати весь bucket. Скрипт `tools/demo/storage-report.mjs` виконується в довіреному середовищі, переглядає об'єкти bucket сторінками та записує `system_metrics/storage`. Мобільний додаток має лише адміністративне читання звіту; клієнтські записи заборонені.

Звіт містить bytes, files, bucket, updatedAt (серверний timestamp), budgetBytes (необов'язково). Це обсяг актуальних об'єктів на час сканування; він не враховує трафік, операції, історичні версії й soft-deleted об'єкти та не є рахунком Firebase. Файли, що змінюються під час сканування, можуть дати неточність. Дата звіту показується в UI; через добу він позначається застарілим. Кнопка оновлення дашборда перечитує звіт, але не запускає інвентаризацію.

### Локальна демонстрація

За запущених емуляторів і встановлених залежностей demo:

```powershell
node tools/demo/storage-report.mjs demo-stefanykhub demo-stefanykhub.firebasestorage.app 5368709120
```

Останнє число — лише довільний плановий бюджет у байтах (у прикладі 5 GiB). Його можна опустити. Не є тарифною квотою і не блокує витрати.

### Реальний проєкт

1. Якщо залежності ще не встановлені: `npm ci --prefix tools/demo`.
2. У довіреному середовищі налаштуйте Application Default Credentials для сервісного акаунта з правами переліку Storage-об'єктів та запису Firestore. Файли облікових даних зберігайте поза репозиторієм та APK. Firebase CLI login сам по собі не налаштовує ADC цього скрипта.
3. Візьміть точне ім'я bucket з Firebase Console → Storage (без `gs://`).
4. Запустіть команду, замінивши `YOUR_BUCKET_NAME`:

```powershell
node tools/demo/storage-report.mjs stefanykhub YOUR_BUCKET_NAME
```

Для планового бюджету додайте кількість байтів останнім аргументом. Без нього звіт не показує бюджет. Скрипт оновлює лише службовий документ звіту, не змінює Storage-об'єкти. Публікація в реальному проєкті тут не виконувалася. Повторюйте скрипт вручну або налаштуйте розклад у довіреному серверному середовищі.

## Правила

```powershell
firebase deploy --only firestore:rules --project stefanykhub
```

Нові правила: presence — запис лише власного heartbeat, читання адміністратором; system_metrics — читання адміністратором, запис лише через довірений Admin SDK; collection group activity — читання адміністратором. Складені індекси для реалізованих запитів не потрібні.

Офіційна документація: [collection group та security rules](https://firebase.google.com/docs/firestore/security/rules-query), [перелік Storage-об'єктів сторінками](https://docs.cloud.google.com/storage/docs/samples/storage-list-files-paginated).
